### 6.118.0 source src/composables/useRefetchOnFocus.js (comment)
/**
 * Re-runs `refetch` when the tab/app regains focus or becomes visible again,
 * throttled to once per `ttlMs`.
 *
 * For views that stay mounted while backgrounded (NOT <KeepAlive>-cached, so
 * onMounted won't re-run on return). Use case: a trainer leaves the app open,
 * a court gets reassigned server-side, then comes back — the on-screen data
 * must reflect the change without a manual reload. The API itself is no-cache,
 * so the only staleness is the SPA not re-asking while idle.
 *
 * Native WKWebView/Android: appStateChange is the reliable foreground signal
 * (visibilitychange is unreliable there — see useAvailabilityResumeRefresh);
 * web tab: visibilitychange + focus. One source per environment, no double
 * fire; a failed native registration falls back to the web listeners.
 *
 * `refetch` should be SILENT (no spinner / list-clear), so the refresh swaps in
 * fresh data without flashing the UI on every focus.
 */
