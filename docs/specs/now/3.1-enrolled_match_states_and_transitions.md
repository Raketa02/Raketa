# The Enrolled Match — States and Transitions

*Every state an enrolled match can occupy, the exact condition that puts it there, and the event that moves it on. Derived from the prototype's state table, the Clock and Protection engine, the Cancellation and Rescue engine, and the hold-ladder and commitment rules.*

# PART 0 — WHAT AN ENROLLED MATCH IS

## 0.1 Definition

An **open match** is a listing. Anybody can see it, and it means nothing to you.

The moment you pay for a seat, that same object becomes an **enrolled match** — *your* enrolled match. It now has a lifetime, a money position, and a state that changes without you doing anything.

```
open match  ──[ you pay for a seat ]──▶  enrolled match  ──[ 24h after play ]──▶  history
```

**Enrolment is per player.** The same underlying match is enrolled for four different people, and each of them sees the same state from a different position — the leaver sees a refund question, the three who stayed see a reassurance. The state itself is a property of the match; **the wording is a property of your relationship to it.**

## 0.2 The lifetime

```
┌──────────────────────────────────────────────────────────────────────────────┐
│  ENROLMENT                                                                   │
│                                                                              │
│  you pay          commitment      T−12h   T−4h    T−2h   T−30m  play    end   │
│      │                 │            │       │       │      │      │      │   │
│      ▼                 ▼            ▼       ▼       ▼      ▼      ▼      ▼   │
│  ────●─────────────────●────────────●───────●───────●──────●──────●──────●─── │
│      │                 │            │       │       │      │      │      │   │
│   the card         refunds      2-seat   3-seat  check-  join    door   result│
│   appears          become        hold     hold    point  closes  code  window │
│   on Now           outcome-      lapses   lapses                              │
│                    based         ·rescue opens·                               │
│                                                                              │
│                                                            end + 24h ─────────┤
│                                                            card leaves Now    │
└──────────────────────────────────────────────────────────────────────────────┘
```

**Start:** the instant your payment lands. Not when you tapped join — an invited seat that has not been paid is held, not enrolled, and holding a seat never holds a court.

**End:** twenty-four hours after the match ends. That window covers entering a result, confirming the other side's, and seeing your level move — three things a player does the morning after, not the minute after.

**Early exits:** you leave, or the match is cancelled. Both are terminal states with their own cards; neither removes the card immediately, because the explanation is the point.

## 0.3 Why this is harder than it looks

A naive model would have five states: forming, confirmed, playing, played, cancelled. That model is wrong here, and the reason is that **an enrolled match has three independent axes**, and the interesting states are combinations.

| Axis | Values | Governed by |
|---|---|---|
| **Court certainty** | none · soft hold · hard hold · released · lost | The hold ladder (Rules 1–12) |
| **Group completeness** | 1 of 4 · 2 of 4 · 3 of 4 · full · full-then-short | Seat payments |
| **Commitment** | free · committed · settled | The commitment rules (A–G) |

A match can be **full with no court**. It can have a **court with two players**. It can be **committed and short**. It can be **past its deadline and free to leave**. Every one of those is a real, reachable, common state, and a five-state model collapses them into lies.

**The two dangerous collapses:**

*Full does not mean committed.* A match that fills three days early is fully paid, firmly holding a court, and **every player is still free to leave and get everything back** — because the deadline has not arrived.

*Past the deadline does not mean committed.* An incomplete match at T−1h commits nobody. The clock passing is not enough. **Both conditions must hold at once.**

## 0.4 What this document is for

Three audiences, one specification.

**Engineers** get the exact guard for every state, in the exact order they must be evaluated, and every event that causes a transition.

**Designers** get the complete list of situations a card has to be able to say something true about.

**Product** gets the answer to *"what does the player see when X happens"* for every X.

# PART 1 — THE STATE MODEL

## 1.1 No state is stored

**This is the single most important structural fact in the document.**

There is no `status` column. Nothing writes `state = 'CONFIRMED'`. The state is **recomputed from scratch every time anybody looks at the match**, from the record plus the current instant.

> *"Everything derives from `S.now` and the match record. There are no timers, no intervals, and no scheduled jobs — the app recomputes on every render, so moving the clock backwards is as valid as moving it forwards."*

**What this buys, and it is not a small list:**

| Property | Consequence |
|---|---|
| No state can be stale | There is nothing to become stale |
| No scheduled job can fail to run | There are none |
| A card is correct offline | The record plus the device clock is enough |
| The clock can be scrubbed backwards | Every derived value un-does correctly |
| No two clients can disagree | They run the same function on the same record |
| Adding a state is a guard, not a migration | No stored value changes |

**The cost, and it is worth it:** every read is a computation. That computation is *"a handful of integer comparisons per match"* — cheaper than the database lookup it replaces.

## 1.2 The facts that are stored

Everything else is derived from these. **A fact is persisted if and only if it records something irreversible**, or something that was chosen rather than computed.

| Fact | Type | Written when | Irreversible? |
|---|---|---|---|
| `seats[].p` | player id \| null | Somebody takes or leaves a seat | no |
| `seats[].paid` | boolean | Payment lands · reversal clears it | no |
| `seats[].at` | instant | Payment lands | no |
| `share` | money | **At creation, once. Never re-priced** | **yes** |
| **`committedAt`** | instant \| null | Both commitment conditions first hold | **yes — never unwritten** |
| `courtId` | court id \| null | The ladder is satisfied and a court is picked | no |
| `protectedAt` | instant \| null | A court is first assigned | no |
| `holdKind` | `hard` \| `soft` \| null | Recomputed on assignment | no |
| `releasedAt` | instant \| null | A held court goes back | no |
| `vacated` | player id \| null | A committed player leaves | no |
| `vacatedAt` | instant \| null | Same moment | no |
| `rescueTaken` | boolean | A discounted replacement pays | **yes** |
| `transferring` | boolean | The leaver arranges a named handover | no |
| `inventoryLost` | boolean | Category sells out while unsecured | **yes — terminal** |
| `clubCancelled` | boolean | Club or weather cancels | **yes — terminal** |
| `formCancelled` | boolean | Checkpoint reached, never completed | **yes — terminal** |
| `checkpointCancelled` | boolean | Checkpoint reached, committed but short, rebooking club | **yes — terminal** |
| `courtLocked` | boolean | A manager commits a court by hand | no |
| `score` / `confirmed` / `noShow` | — | After play | no |

### `committedAt` is the one that matters

> *"The one piece of persisted state is `m.committedAt`, and it is persisted precisely because it must **not** be recomputed: it records that a threshold was crossed, and crossing it is irreversible."*

**Why it cannot be derived.** Commitment requires *deadline passed **and** match full*. If a player leaves after commitment, the match is no longer full — so a derived `committedNow` would compute **false** and retroactively release three people who were already bound.

> *"Without it, one person dropping out at T−3h would retroactively release the other three."*

**Everything downstream depends on this one boolean not lying:** whether the leaver gets 100% or an outcome-based refund, whether the court stays hard-held, whether the rescue cascade may run, and what the checkpoint does at T−2h.

## 1.3 The derived quantities

Computed on every read. None is stored.

```js
filled(m)         = seats where p AND paid          // ← paid, not merely occupied
isFull(m)         = every seat p AND paid
everFull(m)       = committedAt != null || isFull(m)
isProtected(m)    = courtId != null                 // a court is currently assigned

deadlines(m) = {
  commit  : min(start − club.window·h, start − 12h),
  rescue  : start − (singles ? 6 : 4)·h,
  check   : start − 2h,
  joinCut : start − (club.joinCut ?? 30)·min,
  play    : start,
}
matchEnd(m)       = start + duration
resultWindow(m)   = matchEnd + 30 min
keepUntil(m)      = matchEnd + 24 h

courtHold(m, now) = { kind: hard|soft|none, why }   // the ladder, Part 2.1
committedNow(m,now)= committedAt != null || (now ≥ commit AND isFull)
committedOnFill(m)= committedAt != null AND committedAt > commit + 60s
```

**`filled` counts paid seats only.** An invited seat with no payment counts for neither `filled` nor `isFull`.

> *"Holding a seat never holds a court. Only money does."*

## 1.4 The resolution ladder

**The order is the specification.** States are tested top to bottom; the first match wins. Reordering these lines changes behaviour, and two of the orderings are load-bearing enough that a test must prove each beats the one below it.

```
 1  inventoryLost                                    → inventoryLost
 2  clubCancelled OR weather                         → cancelledClub
 3  formCancelled                                    → cancelledIncomplete
 4  checkpointCancelled                              → cancelledCheckpoint
 5  now ≥ matchEnd                                   → the post-play group   ▼
      noShow                                            → playedNoShow
      filled < n                                        → playedShort
      confirmed                                         → completed
      now ≥ resultWindow                                → playedNoScore
      score entered                                     → confirmResult
      otherwise                                         → needsResult
 6  not my seat AND on the waitlist                  → waitlisted
 7  kind = private                                   → the private group     ▼
 8  vacated AND committedAt ≠ null                   → the recovery group    ▼
      transferring                                      → replacementTransfer
      now ≥ check                                       → rescueLate
      now ≥ rescue                                      → rescue
      otherwise                                         → replacement
 9  vacated (i.e. not committed when they left)      → isProtected ? protectedBack : formingBack
10  isFull                                           → the full group        ▼
      now ≥ start − 15min                               → ready
      committedAt ≠ null                                → committedOnFill ? confirmedOnFill : confirmed
      otherwise                                         → full
11  isProtected                                      → the court group       ▼
      hold.why = 'club'                                 → clubHeld
      hold.kind = 'soft'                                → heldSoft
      now ≥ commit                                      → protectedLate
      otherwise                                         → protectedCourt
12  releasedAt ≠ null AND filled ≥ 2 AND now < check  → heldReleased
13  any seat occupied but unpaid                     → formingHeld
14  now ≥ commit                                     → formingLate
15  otherwise                                        → forming
```

### The four orderings that carry weight

**Cancellation beats everything, including play (1–4 before 5).** A club that cancels at 19:00 for a 18:30 match still reads as *cancelled*, not as *played*. The player did not play.

**Inventory loss beats club cancellation (1 before 2).** Both set `clubCancelled`, so without the earlier test every inventory loss would read as a weather cancellation — and the two have completely different stories. Inventory loss is *"the last compatible court was sold while this match was still short"*, which is the one risk a player genuinely carries and which the product names from the first screen.

**Recovery beats full and beats forming (8–9 before 10–11).** A committed match that lost a player has `filled = n−1`, which would otherwise fall through to the court group and read as *"Court protected · one player needed"* — indistinguishable from an ordinary forming match, and a catastrophic thing to tell somebody whose money is at stake.

**Full beats protected (10 before 11).** A full match is also protected. Reversing these would report the court state on a match whose group is complete, which is the less useful of the two facts.

# PART 2 — THE RULES THAT DRIVE THE STATE

## 2.1 The court hold ladder

**The question every rule answers:** *right now, is a physical court being kept aside for this match?*

**The underlying idea:** a club holding a court is refusing to sell it to somebody else. So **the certainty required to justify that bet rises as the hour approaches**, because the closer play gets, the harder it is for the club to resell if the match falls through.

### The twelve rules

| # | Rule | Result |
|---|---|---|
| **1** | A privately booked court is held permanently | `hard · private` |
| **2** | A court the club commits by hand is held permanently — this overrides every automatic release below | `hard · club` |
| **3** | Once a match has committed, its court is held permanently | `hard · committed` |
| **4** | A full match holds a court immediately and firmly | `hard · full` |
| **5** | Three of four, more than four hours out: held **softly** | `soft · near` |
| **6** | Three of four, inside four hours: the court goes back | `none · nearLapsed` |
| **7** | Two of four, more than twelve hours out: held softly | `soft · far` |
| **8** | Two of four, inside twelve hours: the court goes back | `none · farLapsed` |
| **9** | One seat or none: no court is ever held | `none · thin` |
| **10** | Two-player sports skip the soft tiers entirely | `none` until full |
| **11** | A club may set a maximum age for a soft hold | club setting, not a marketplace rule |
| **12** | A club may hold **longer** than the ladder promises, never shorter | the ladder is a floor |

```
paid seats
    4  │████████████████████████████████████████████████│  hard, always
    3  │███████████████████████████████████░░░░░░░░░░░░░│  soft until T−4h
    2  │████████████████░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░│  soft until T−12h
   0-1 │░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░│  never
       └────────────────┬──────────────────┬───────────┘
                     T−12h              T−4h        play
```

### Why the direction looks backwards, and is right

Two paid seats hold a court three days out and **release** it twelve hours out. From the player's side that reads as the app getting less helpful as the match approaches.

> *"From the club's side it is exactly right: far out, holding costs almost nothing because there is a week to resell if the match dies; close to play, the same hold may turn away a paying private booking that will not come again."*

### Singles has no middle ground

> *"With `n=2`, one short of full is one player — too little to justify holding anything. Half a booking is a much weaker signal than three-quarters of one."*

A squash or tennis court is held **only when the match is complete**. Stricter than doubles, and correct.

### `committed` is the tier that makes the ladder safe

Rule 3 is not a convenience. Without it, a committed match that loses a player drops to `filled = n−1` and would **release its court at T−4h under Rule 6** — taking the court away from three people who are already bound and cannot leave for free.

### Release is real, and reversible

> *"The court is genuinely returned, the player is notified, and the match **stays open and keeps looking**. Losing a court is not losing the match — it comes straight back the moment the ladder is satisfied again. The match itself only ends at the two-hour checkpoint."*

This is why `heldReleased` is a state and not an error.

## 2.2 Certainty and commitment

**A completely different question:** *are the players locked in, or can they still walk away with their money?*

| # | Rule |
|---|---|
| **A** | The commitment moment is whichever comes first: the club's own deadline, or twelve hours before play |
| **B** | **The clock by itself never commits anybody.** If the deadline passes and the match is still short, nobody is committed and everybody may still leave for nothing |
| **C** | Commitment requires two things at once: a full match **and** a passed deadline |
| **D** | A match that completes late commits everybody **on the spot** |
| **E** | A rescue window exists before play — four hours doubles, six singles — inside which a vacated seat may be offered at half price to a targeted pool |
| **F** | A checkpoint two hours before play, which cannot be switched off, decides what happens to a match that is committed but still short |
| **G** | Joining closes twenty or thirty minutes before play, set by the club |

### Rule B is the product

> *"Miss either and nothing is at stake. The clock passing on an incomplete match does not commit the people who paid — it simply means the match did not happen, and their money comes back whole."*

Every competing product converts *"pay by Friday or the match dies"* into *"the deadline arrived, the match is incomplete, and the people who did pay are now committed to a court for a game that will not happen."* Rule B is the refusal to do that.

### Rule C produces a state most models do not have

A match that fills early is fully paid, firmly holding a court, and **every player is still free to leave and get everything back.** That is the `full` state, and it exists for exactly the window between filling and the deadline.

### Rule D produces another

If the deadline has already gone and the final seat is then paid, **commitment happens at that instant.**

> *"Being committed immediately on payment is a different experience from being committed by a clock, and pretending otherwise would be a nasty surprise."*

Hence `confirmedOnFill` as a separate state from `confirmed`, detected by `committedAt > commit + 60s`. The sixty-second tolerance stops a match that filled *right on* the deadline being classified as a late fill.

## 2.3 How the two rule sets compose

They are independent, and the combinations are the state space.

|  | not committed | committed |
|---|---|---|
| **no court** | `forming` · `formingLate` · `heldReleased` | *unreachable — Rule 3 pins the court* |
| **soft hold** | `heldSoft` | *unreachable — Rule 3 makes it hard* |
| **hard hold, short** | `protectedCourt` · `protectedLate` | `replacement` · `rescue` · `rescueLate` |
| **hard hold, full** | `full` | `confirmed` · `confirmedOnFill` · `ready` |

**Two cells are structurally unreachable**, and both for the same reason: Rule 3 promotes any committed match's court to a permanent hard hold, so *committed* and *no court* cannot coexist and neither can *committed* and *soft*.

**That is a useful invariant to assert**, because a bug that produced either would be invisible on screen and catastrophic in effect.

## 2.4 Two coincidences worth knowing about

**T−12h is two different rules.** It is the commitment floor (Rule A) **and** the two-seat hold lapse (Rule 8). At a club with a 12-hour cancellation window they fire at the same instant: the match commits if it is full, and loses its court if it is on two seats. **At a 24-hour club they are twelve hours apart.** Any test that only exercises one club type will miss this.

**T−4h is two different rules.** It is the three-seat hold lapse (Rule 6) **and** the doubles rescue window opening (Rule E). For a doubles match that is short, the court goes back at the same moment the discount becomes available for a seat that was never vacated — the two do not interact, but they land together, and a player watching the card sees one change.

# PART 3 — THE FIVE DRIVERS OF CHANGE

Everything that can move an enrolled match falls into exactly five categories.

| # | Driver | Changes a stored fact? | Example |
|---|---|---|---|
| **1** | **The clock crosses a threshold** | No | T−4h passes and a three-seat hold lapses |
| **2** | **A seat event** | Yes | Somebody pays · somebody leaves · an invite lapses |
| **3** | **A court event** | Yes | The ladder assigns a court · the ladder releases it |
| **4** | **A club or inventory event** | Yes | The club cancels · the category sells out · a manager locks a court |
| **5** | **A post-play event** | Yes | A result is entered · confirmed · nobody enters one |

## 3.1 Driver 1 — the clock alone

**No fact changes. A threshold is crossed and the derivation produces a different answer.**

This is the driver that makes the model unusual: a match can change state, notify four people, and lose a court **with nobody doing anything.**

| Threshold | When | What can change |
|---|---|---|
| `commit` | min(club window, T−12h) | `forming` → `formingLate` · `protectedCourt` → `protectedLate` · **commits if full** |
| **T−12h** | fixed | Two-seat soft hold lapses → court released |
| **T−4h** | fixed | Three-seat soft hold lapses → court released |
| `rescue` | T−4h doubles · T−6h singles | `replacement` → `rescue` |
| `check` | T−2h | **The checkpoint fires** — see 3.6 |
| `joinCut` | T−30min · T−20min | No new player can join. The cascade stops |
| `start − 15min` | fixed | `confirmed` → `ready`, door code live |
| `start` | — | Play begins |
| `matchEnd` | start + duration | Post-play group opens |
| `resultWindow` | end + 30min | `needsResult` → `playedNoScore` |
| `keepUntil` | end + 24h | The card leaves Now |

## 3.2 Driver 2 — a seat event

| Event | Fact written | Effect |
|---|---|---|
| A player pays | `seats[i].p`, `.paid`, `.at` | `filled` +1 → re-evaluate the ladder → possibly a court, possibly full, possibly commitment |
| A player is invited | `seats[i].p`, `paid = false` | `filled` unchanged. **The seat is held, not funded** |
| An invite lapses | `seats[i].p = null` | The seat reopens |
| **Leaves, not committed** | seat cleared, **`paid = false`** | Full reversal. `filled` −1 → the ladder may release the court |
| **Leaves, committed** | `vacated`, `vacatedAt`, **`paid` stays true** | Recovery group. **The court is safe** |
| Full-price replacement pays | `rescueTaken = true`, seat re-occupied | Leaver refunded 100% |
| Rescue player pays 50% | seat re-occupied | Leaver refunded 50% |
| Transfer arranged | `transferring = true` | `replacement` → `replacementTransfer` |

### The one line that decides everything about leaving

```js
seat.paid = (outcome !== 'reversal');
```

**Before commitment** the seat becomes empty **and unpaid.** `filled` drops, the ladder may release the court, and the match falls back to forming. The leaver gets everything back in minutes.

**After commitment** the seat becomes empty **but stays paid.** The club has been paid, the court is not at risk, and the other three are untouched. That single comparison is what lets the product promise *"nothing about your booking changes"* to the players who stayed.

**This is why `formingBack` and `replacement` are different states rather than one.** They are the same human event — somebody left — on opposite sides of one deadline, and the consequences are completely different.

## 3.3 Driver 3 — a court event

Court events are **not** independent. They are the ladder's output, recomputed whenever `filled` or the clock changes.

```
                 ┌─────────────────────────┐
   filled ──────▶│                         │
                 │   courtHold(m, now)     │──▶ kind: hard | soft | none
   now    ──────▶│   (the twelve rules)    │
                 └─────────────────────────┘
                              │
        kind ≠ none ──────────┼────────── kind = none AND committedAt = null
              │                                        │
              ▼                                        ▼
     assign a court if we have none              release the court
     write courtId, protectedAt, holdKind        clear courtId, protectedAt, holdKind
     (or LOSE INVENTORY if none is free)         write releasedAt
```

| Event | Trigger | Effect |
|---|---|---|
| Court assigned | Ladder satisfied and none held | `courtId`, `protectedAt`, `holdKind` written |
| Hold firms | soft → hard, on the payment that fills or commits | `holdKind = 'hard'` |
| **Court released** | Ladder no longer satisfied **and** not committed | `courtId` cleared, `releasedAt` written |
| Club locks a court | A manager acts | `courtLocked = true` → `hard · club`, overrides everything below |
| **Inventory lost** | Ladder wants a court, none is free, before the checkpoint | `inventoryLost`, `clubCancelled` — **terminal** |

**A committed match never releases.** The `else if (committedAt == null)` guard on the release branch is Rule 3 in code.

## 3.4 Driver 4 — a club or inventory event

| Event | Fact | Terminal? |
|---|---|---|
| Club cancels · weather | `clubCancelled` | **yes** |
| Category sells out while unsecured | `inventoryLost` + `clubCancelled` | **yes** |
| Manager commits a court by hand | `courtLocked` | no — improves the state |

### Inventory loss is the one real risk in an open match

> *"An unsecured match whose category has sold out cannot be fulfilled. It is cancelled and everybody is refunded in full — including anybody who had already left. This is the one risk a player genuinely carries in an open match, and it is named on the Forming card from the moment they pay rather than buried in terms."*

It fires only for a match that is **unsecured**, **uncommitted**, and **before the checkpoint**. A complete match that cannot find a court reaches the same end from the `hard` branch of the ladder.

**Everybody is refunded in full, including anybody who had already left.** That last clause is unusual and deliberate: a player who left at T−20h and took a 50% outcome gets the other 50% back, because the match they left never happened.

## 3.5 Driver 5 — a post-play event

| Event | Effect |
|---|---|
| Nobody entered a result within 30 min | `needsResult` → `playedNoScore` — counts for nobody, all four lose a Player Score point |
| Somebody entered a result | `needsResult` → `confirmResult` for the other side |
| The other side confirmed | → `completed`, levels move |
| A player did not turn up | `noShow` → `playedNoShow` |
| The match played short | `filled < n` at the end → `playedShort` |

**Any of the four can enter the result** — not the creator, not a nominated scorer. Confirmation must come from **the other side**, because a teammate agreeing with a teammate proves nothing.

## 3.6 The checkpoint — T−2h, and it cannot be switched off

The single most consequential clock event, and the only one that branches on club policy.

```
                        now ≥ T−2h
                             │
              ┌──────────────┴──────────────┐
              ▼                             ▼
      committedAt = null              committedAt ≠ null
      AND not full                    AND filled < n
              │                             │
              ▼                    ┌────────┴────────┐
      formCancelled = true         ▼                 ▼
              │              rebooking club    standard club
              ▼                    │                 │
    ┌─────────────────────┐        ▼                 ▼
    │ cancelledIncomplete │  checkpointCancelled  NOTHING —
    │ everybody refunded  │  three credited       stays in rescueLate,
    │ 100%, nobody was    │  at the club,         cascade runs to joinCut,
    │ ever committed      │  leaver forfeits      may play short or bring a guest
    └─────────────────────┘  their share
```

**Three outcomes from one moment**, and which one you get depends on two facts the player cannot control: whether the match ever committed, and which club they booked at.

**The third outcome is the absence of an event.** A committed, short match at a standard club is not cancelled at the checkpoint — it stays alive, the rescue cascade keeps running to the join cutoff, and the group may bring a guest or play a player short. The card says so.

# PART 4 — THE RESCUE CASCADE

*Driver 2's most complex consequence, and the reason the recovery group has four states rather than one.*

## 4.1 What triggers it

Six conditions, **all required**, none weakened by any later stage.

```js
rescueCore(m) =
     m.vacated != null          // a previously confirmed player left
  && everFull(m)                // the match had actually reached full
  && m.committedAt != null      // and it was committed when they left
  && !m.rescueTaken             // no full-price replacement has joined
  && now >= d.rescue            // the targeted phase has opened
  && now <  d.joinCut           // and the club still accepts online joins
```

## 4.2 The six rungs

| Rung | What it does | Price | Consent | Skippable |
|---|---|---|---|---|
| **Phase A** | Full-price nudge to standby, **immediately on vacancy** | full | no | never — costs nothing to send |
| **Stage 1** | Standby pool, in a ranked wave | **50%** | no | if empty |
| **Stage 2** | Intent pool, inside the band | **50%** | no | if empty |
| **Stage 3** | Widen the level band | 50% | **unanimous** | if empty or policy off |
| **Stage 4** | Shift ±30/60/90 min | same | **unanimous** | if no slot or policy off |
| **Stage 5** | Merge with another short match | same | **unanimous, both sides** | if none or policy off |

```
 vacancy                                     T−4h/−6h                joinCut    play
    │                                           │                        │        │
    ├── Phase A: full-price nudge ──────────────┤                        │        │
    │                                            ├─ Stage 1: standby ────┤        │
    │                                            ├─ Stage 2: intent ─────┤        │
    │                                            ├─ Stage 3: widen ──────┤        │
    │                                            ├─ Stage 4: shift ──────┤        │
    │                                            ├─ Stage 5: merge ──────┤        │
    │                                                                    ├ closed ┤
```

**Phase A needs no window.** A free, harmless, full-price notice that can only help has no reason to wait for a deadline that exists purely to gate the **discount**, not the **notice**.

**A stage with no candidate is skipped instantly, costing no time at all** — there is nothing to wait for if nothing was tried. A stage that *fires* waits twenty minutes before the next is attempted.

## 4.3 What the cascade does and does not change

| Changes | Never changes |
|---|---|
| Who is in the seat | What the three who stayed paid |
| The level band, **with unanimous consent** | The 50% price |
| The time, **with unanimous consent** | That a Rescue Seat is invisible |
| Which match it is, **with unanimous consent** | That consent is unanimous |
| The leaver's refund outcome | The club's join cutoff |

> *"The engine may try anything computable; it may never decide anything a player did not consent to."*

**A single decline ends that rung and changes nothing for anybody.** The next rung is attempted.

## 4.4 Where the cascade shows up in the state model

**It does not produce its own states.** The four recovery states are driven by the clock and by `transferring`, not by which rung is currently firing:

```
replacement          vacated + committed, before d.rescue     — Phase A + marketplace only
rescue               vacated + committed, at/after d.rescue   — Stages 1–5 running
rescueLate           vacated + committed, at/after check      — standard club, still running
replacementTransfer  transferring = true                      — a named handover, any time
```

**A player cannot see which rung is firing, and that is deliberate.** Exposing *"we are on stage 4 of 5"* would tell them how close the match is to failing, which is information the engine does not have and the player cannot act on. What they see instead is the constant that matters: **your payment will not change.**

**The exception is a consent request**, which is not a state change at all — it is a notification with two buttons, and declining it leaves the state exactly where it was.

# PART 5 — THE STATES

*Twenty-eight core states in eight groups, plus one antechamber and four private-court states. Each entry gives the exact guard, every route in, every route out, and what the card says.*

**Reading a state entry:**

```
### `key` — Tag                              ← the ST table key, and the pill the player sees
Tone · Backend state · Context               ← colour, model state, the line under the tag
GUARD          the exact condition, assuming every earlier rung of §1.4 failed
IN             (previous state ← event)
OUT            (event → next state)
COURT / GROUP  the two facets
```

---

## GROUP 1 — FORMING · no court is held

*The default state of a new enrolled match. The group is incomplete and the club is still selling the slot.*

### `forming` — **Forming**
`idle` · `FORMING` · *no court held yet*

**GUARD** — not cancelled · before play · not vacated · not full · **no court held** · every occupied seat paid · `now < commit`

**IN**
- **enrolment** ← you pay for a seat in a match with 0–1 other paid seats
- `formingHeld` ← the invited seat lapses or is paid *(if paid and this makes 2+, the ladder may fire)*
- `heldReleased` ← 24 hours pass and the release is no longer the news

**OUT**
- a second seat is paid, >12h remain → **`heldSoft`**
- a third seat is paid, >4h remain → **`heldSoft`** *(soft, `near`)*
- the last seat is paid → **`full`**, or **`confirmedOnFill`** if past `commit`
- a seat is invited but unpaid → **`formingHeld`**
- `now ≥ commit` → **`formingLate`**
- a paid player leaves → stays **`forming`**, `filled` drops
- the category sells out inside 12h → **`inventoryLost`**
- `now ≥ check` still incomplete → **`cancelledIncomplete`**

**COURT** Not held — the club is still selling this slot
**GROUP** *n* of 4 seats paid

**The line that must be on this card from the first moment:** *"Until then the club could sell its last compatible court — if that happens the match is cancelled and everybody is refunded in full."* This is the only genuine risk in an open match and the product names it up front rather than burying it.

---

### `formingHeld` — **Forming**
`idle` · `FORMING` · *a seat is held for an invited player*

**GUARD** — as `forming`, but **some seat is occupied and unpaid**

**IN**
- `forming` ← a player invites somebody

**OUT**
- the invitee pays → **`forming`** / **`heldSoft`** / **`full`**, per the new count
- the hold expires → **`forming`**, the seat reopens
- `now ≥ commit` → **`formingLate`** *(the hold is truncated to `commit` and cannot outlive it)*

**COURT** Not protected — no court is held yet
**GROUP** *n* of 4 paid · 1 seat held

**The hold rules.** Base two hours. **Thirty minutes** if the match is under four hours away. **Never lapses overnight** — a hold expiring between 22:00 and 08:00 is pushed to 08:00. **Never past commitment** — truncation wins, because *"commitment is a hard constraint and civility is a soft one."*

**A held seat does not count toward `filled`.** It holds nothing and buys nothing.

---

### `formingLate` — **Forming**
`idle` · `FORMING` · *the deadline has passed and the match is still incomplete*

**GUARD** — as `forming`, plus `now ≥ commit`

**IN**
- `forming` / `formingHeld` ← **the clock crosses `commit`** *(Driver 1 — no fact changed)*
- **enrolment** ← you join a match created inside its own commitment window

**OUT**
- the last seat is paid → **`confirmedOnFill`** — commits everybody **on the spot**
- a seat is paid, not the last → stays **`formingLate`**
- `now ≥ check` → **`cancelledIncomplete`**
- the category sells out → **`inventoryLost`**

**COURT** Not protected — no court is held yet
**GROUP** *n* of 4 seats paid

**This state has two context lines, and the difference matters.**

| Condition | Context |
|---|---|
| `created < commit` — an ordinary match that ran late | *"the deadline has passed and the match is still incomplete"* |
| `created ≥ commit` — created inside its own window | *"it commits as soon as it is complete"* |

> *"Saying 'the deadline has passed' would read as a warning about something the player just did on purpose."*

**Nobody is committed here.** This is Rule B in its purest form: the deadline passed, the match is short, and every player may still leave for a full refund.

---

### `formingBack` — **Forming**
`watch` · `FORMING` · *a player left before commitment*

**GUARD** — `vacated` is set, `committedAt` is null, **no court held**

**IN**
- `heldSoft` / `heldReleased` ← a paid player leaves before commitment, and the drop releases the court

**OUT**
- a seat is paid → **`heldSoft`** or **`protectedCourt`** as the ladder allows
- 24 hours pass with no further change → **`forming`**
- `now ≥ check` → **`cancelledIncomplete`**

**COURT** Released — the court is no longer held
**GROUP** *n* of 4 seats paid

**Tone is `watch`, not `idle`.** Something happened. The seat is genuinely open again at the normal price, and the leaver was reversed in full — *"your price does not change"* is the line that matters.

---

## GROUP 2 — COURT HELD · the ladder is satisfied, softly

### `heldSoft` — **Court held**
`watch` · `COURT_HELD` · *two paid seats* **or** *one player short*

**GUARD** — a court is held and `holdKind = 'soft'`

**IN**
- `forming` ← a second seat is paid with >12h remaining *(Rule 7)*
- `forming` ← a third seat is paid with >4h remaining *(Rule 5)*
- `heldReleased` ← another seat is paid and the ladder is satisfied again

**OUT**
- **the clock crosses T−12h on two seats** → **`heldReleased`** *(Rule 8)*
- **the clock crosses T−4h on three seats** → **`heldReleased`** *(Rule 6)*
- another seat is paid → **`protectedCourt`** *(3 seats, >4h)* or **`full`**
- a paid player leaves → **`formingBack`**
- the club locks the court by hand → **`clubHeld`**

**COURT** Held · *category* — *the ladder's own note*
**GROUP** *n* of 4 seats paid

**Two different situations share one tag**, distinguished by the context line:

| `why` | Context | Lapses at |
|---|---|---|
| `far` | two paid seats | T−12h |
| `near` | one player short | T−4h |

> *"'Softly' is a real distinction, not a euphemism — it means the hold may still evaporate."*

The card says so: *"A court is being held, but this is not yet a firm booking."*

**Singles never reaches this state.** Rule 10 skips the soft tiers entirely.

---

### `heldReleased` — **Court released**
`watch` · `COURT_RELEASED` · *still short, close to play*

**GUARD** — `releasedAt` is set · `filled ≥ 2` · `now < check` · no court currently held

**IN**
- `heldSoft` ← **the clock crosses T−12h on two seats** *(Rule 8)*
- `heldSoft` ← **the clock crosses T−4h on three seats** *(Rule 6)*
- `protectedCourt` ← a player leaves and the drop breaks the ladder

**OUT**
- a seat is paid → **`heldSoft`** / **`protectedCourt`** / **`full`** — *the court comes straight back*
- the category sells out first → **`inventoryLost`**
- `now ≥ check` still incomplete → **`cancelledIncomplete`**

**COURT** Released — back on sale at *club*
**GROUP** *n* of 4 seats paid

**This state exists because silence would be worse than bad news.**

> *"A court that was held and went back is its own state — the player paid for a match that briefly had a court and now does not, and silence there would be the single most alarming gap on the screen."*

**Nothing the player paid is affected.** The money is untouched and refundable in full. The match is still open and still looking, and the court returns the moment another seat is paid. The card's third line says which: *"One more paid seat brings a court back"* or *"The last seat books a court on the spot."*

**A production system must guard against oscillation.** A match sitting exactly on T−12h with two paid seats will flap between `heldSoft` and `heldReleased` on every recomputation if the comparison is not strictly one-directional. Use `>` on the remaining time, never `>=`, and never re-notify on the same transition twice.

---

### `clubHeld` — **Court committed**
`good` · `COURT_PROTECTED` · *the club put a court behind it*

**GUARD** — `courtLocked` is true → the ladder returns `hard · club`

**IN**
- any forming or held state ← **a manager commits a court by hand** *(Rule 2)*

**OUT**
- the last seat is paid → **`full`** / **`confirmedOnFill`**
- `now ≥ check` still incomplete → **`cancelledIncomplete`** *(the lock holds the court, not the match)*

**COURT** Committed by *club* · *category*
**GROUP** *n* of 4 seats paid

**Rule 2 overrides every automatic release below it.** The court stays whatever the seat count does. *"Clubs do this for matches they expect to fill, or to keep a regular group together."*

**It does not commit the players.** Leaving still returns everything, in minutes. The club committed a court; nobody committed a person.

---

## GROUP 3 — COURT PROTECTED · a hard hold, group still short

### `protectedCourt` — **Court protected**
`good` · `COURT_PROTECTED` · *one player needed*

**GUARD** — a court is held, `holdKind = 'hard'`, not full, `now < commit`

**IN**
- `heldSoft` ← a third seat is paid with >4h remaining
- `formingBack` / `heldReleased` ← a seat is paid and the ladder is satisfied

**OUT**
- the last seat is paid → **`full`**
- `now ≥ commit` → **`protectedLate`**
- a player leaves → **`protectedBack`** *(if the ladder still holds)* or **`heldReleased`**
- the clock crosses T−4h at three seats → **`heldReleased`**

**COURT** Protected · *category* — a private booking can no longer take it
**GROUP** *n* of 4 seats paid

**The exact court is assigned, never chosen — and the price cannot change.** The category was bought, not the court, which is what lets a seat price be quoted before a court exists and stay fixed when one is assigned.

---

### `protectedLate` — **Court protected**
`good` · `COURT_PROTECTED` · *past the deadline, still free to leave*

**GUARD** — as `protectedCourt`, plus `now ≥ commit`

**IN**
- `protectedCourt` ← **the clock crosses `commit`** *(Driver 1)*

**OUT**
- the last seat is paid → **`confirmedOnFill`** — commits everybody at once
- the clock crosses T−4h → **`heldReleased`** *(Rule 6, three seats)*
- `now ≥ check` → **`cancelledIncomplete`**

**COURT** Protected · *category*
**GROUP** *n* of 4 seats paid

**The clearest demonstration of Rule B in the whole model.** The deadline has passed. A court is hard-held. Money has been taken from three people. **And every one of them may still leave and get everything back**, because the match is not complete.

*"The last seat commits everybody the moment it is paid."*

---

### `protectedBack` — **Court protected**
`good` · `COURT_PROTECTED` · *a player left before commitment*

**GUARD** — `vacated` set, `committedAt` null, **a court is still held**

**IN**
- `full` ← a player leaves before commitment, leaving three paid with >4h remaining
- `protectedCourt` ← same, from four

**OUT**
- the seat is retaken → **`full`**
- the clock crosses T−4h → **`heldReleased`**
- `now ≥ check` → **`cancelledIncomplete`**

**COURT** Still held · *category* — three seats are still paid
**GROUP** *n* of 4 seats paid

**The contrast with `formingBack` is the whole point.** Same event — somebody left before commitment — but here the remaining three still satisfy the ladder, so the court survives. *"Their seat is open again at the normal price."*

---

## GROUP 4 — FULL · complete, not yet committed

### `full` — **Full**
`good` · `FULL_UNCOMMITTED` · *free cancellation until the deadline*

**GUARD** — `isFull` · `committedAt` is null · `now < start − 15min`

**IN**
- any forming or protected state ← **the last seat is paid**, before `commit`
- `replacement` / `rescue` ← the seat is refilled *before* commitment *(rare — the match was never committed)*

**OUT**
- **`now ≥ commit`** → **`confirmed`** — this is the commitment moment *(Driver 1)*
- a player leaves → **`protectedBack`** *(court survives)* or **`formingBack`**
- `now ≥ start − 15min` → **`ready`**
- the club cancels → **`cancelledClub`**

**COURT** Reserved · settles to the club at *commit*
**GROUP** 4 of 4 seats paid

**Rule C's state, and it is the one most models do not have.** Every seat paid. A court hard-held. Nothing settled, nothing committed, and **free cancellation for everybody** until the deadline.

*"Nothing has reached the club yet."*

**This is the only state a full match can be in before `commit`**, and it can last for days — a match that fills on Wednesday for Saturday sits here until Friday evening.

---

## GROUP 5 — CONFIRMED · committed and complete

### `confirmed` — **Confirmed**
`good` · `CONFIRMED` · *committed at the deadline*

**GUARD** — `isFull` · `committedAt` ≠ null · **not** `committedOnFill` · `now < start − 15min`

**IN**
- `full` ← **the clock crosses `commit`** while the match is full *(Driver 1)*

**OUT**
- a player leaves → **`replacement`** *(before `rescue`)* or **`rescue`** *(after)*
- `now ≥ start − 15min` → **`ready`**
- the club cancels → **`cancelledClub`**

**COURT** *price* settled to the club
**GROUP** 4 of 4 · committed

**The money settled and the match is confirmed.** From here, *"if you cannot come now, your seat is searched for rather than refunded."* That sentence is the whole difference between this state and `full`, and it is the moment the refund model changes from *reversal* to *outcome-based*.

---

### `confirmedOnFill` — **Confirmed**
`good` · `CONFIRMED` · *the last seat filled after the deadline*

**GUARD** — as `confirmed`, plus `committedAt > commit + 60s`

**IN**
- `formingLate` / `protectedLate` ← **the last seat is paid after `commit`** *(Rule D)*

**OUT** — identical to `confirmed`

**COURT** *price* settled to the club
**GROUP** 4 of 4 · committed on the spot

**A separate state because it is a different experience.**

> *"Being committed immediately on payment is a different experience from being committed by a clock, and pretending otherwise would be a nasty surprise."*

*"Court assigned, money settled, match confirmed — in one step."* And crucially: *"Everyone knew that joining the last seat would do this"* — the player who paid last was told before they paid.

**The 60-second tolerance** stops a match that filled *right on* the deadline being labelled a late fill.

---

## GROUP 6 — RECOVERY · committed and short

*Four states, all reached by the same event — a committed player left — and separated by the clock and by whether a named handover is in progress.*

### `replacement` — **Replacement pending**
`watch` · `REPLACEMENT_PENDING` · *full-price search*

**GUARD** — `vacated` set · `committedAt` ≠ null · `now < rescue` · not transferring

**IN**
- `confirmed` / `confirmedOnFill` / `ready` ← **a committed player leaves**

**OUT**
- somebody pays full price → **`confirmed`**, `rescueTaken = true`, leaver refunded **100%**
- `now ≥ rescue` → **`rescue`** *(Driver 1)*
- the leaver arranges a handover → **`replacementTransfer`**
- the club cancels → **`cancelledClub`**

**COURT** *price* settled to the club
**GROUP** 3 of 4 · the seat stays funded

**ALERT** — *"{Name} left after the commitment deadline. We are looking for a replacement.* **Your payment will not change.**"

**The alert is the state.** This is one of only two states that raises a highlighted strip, and the bold clause is always the money clause. *"Their payment stays on the seat, so the court is safe."*

**Phase A of the cascade has already fired** by the time this card renders — a full-price nudge went to the standby pool the instant the seat was vacated, without waiting for any window.

---

### `replacementTransfer` — **Replacement pending**
`watch` · `REPLACEMENT_PENDING` · *a transfer is being arranged*

**GUARD** — as `replacement`, plus `transferring` is true

**IN**
- `replacement` / `rescue` ← the leaver names somebody they know

**OUT**
- the named person pays → **`confirmed`**
- the transfer falls through → back to **`replacement`** / **`rescue`** by the clock

**COURT** *price* settled to the club
**GROUP** 3 of 4 · the seat stays funded

**A named person always pays full price, or is given the seat outright.** *"Half price is never hers to hand out."* The discount is the platform's instrument for filling a seat nobody wants; it is not a favour a leaver can grant.

---

### `rescue` — **Rescue active**
`time` · `RESCUE_ACTIVE` · *targeted 50/50 invitations*

**GUARD** — `vacated` set · `committedAt` ≠ null · `now ≥ rescue` · `now < check` · not transferring

**IN**
- `replacement` ← **the clock crosses `rescue`** (T−4h doubles, T−6h singles) *(Driver 1)*
- `confirmed` / `ready` ← a committed player leaves **after** `rescue` has already opened

**OUT**
- a standby or intent player pays 50% → **`confirmed`**, leaver refunded **50%**
- somebody pays full price → **`confirmed`**, leaver refunded **100%**
- a consent stage succeeds → the match changes band, time or identity — **the state does not**
- `now ≥ check` → **`rescueLate`** *(standard club)* or **`cancelledCheckpoint`** *(rebooking club)*

**COURT** *price* settled to the club
**GROUP** 3 of 4 · the seat stays funded

**ALERT** — *"Still looking for a replacement.* **Your payment will not change.**"

**Amber tone, and only here.** A window is open and it will close. `rescue` is the only state in the entire model that uses `time`.

*"Sent to standby players in waves, not advertised as a public sale."* The leaver *"gets half back if a Rescue player pays; nothing if none does"* — the refund is decided by the outcome, never announced in advance.

---

### `rescueLate` — **Rescue active**
`time` · `RESCUE_ACTIVE` · *past the checkpoint, still searching*

**GUARD** — as `rescue`, plus `now ≥ check`, at a club with `rebooking = false`

**IN**
- `rescue` ← **the clock crosses `check`** at a standard club *(Driver 1 — and the interesting case is that **nothing happens**)*

**OUT**
- somebody takes the seat → **`confirmed`**
- `now ≥ joinCut` → the cascade stops; the match plays short → **`playedShort`**
- the group brings a guest → the match plays complete

**COURT** *price* settled to the club
**GROUP** 3 of 4 · the seat stays funded

**This state is defined by the absence of an event.** At a rebooking club the checkpoint cancels the match; at a standard club it does nothing at all, and the card has to say so explicitly or the player will assume the worst at exactly the moment they are most anxious.

*"This club does not offer rebooking credit, so the match stays alive. Rescue runs until {joinCut}, and you can bring a guest, or play three."*

---

## GROUP 7 — READY

### `ready` — **Ready to play**
`good` · `CONFIRMED` · *door code live*

**GUARD** — `isFull` · `now ≥ start − 15min` · `now < matchEnd`

**IN**
- `confirmed` / `confirmedOnFill` ← **the clock crosses T−15min** *(Driver 1)*
- `full` ← same, on a match that never needed to commit *(rare)*

**OUT**
- `now ≥ matchEnd` → the post-play group
- a player leaves → **`rescue`** — with almost no window left
- the club cancels → **`cancelledClub`**

**COURT** Court *{assigned court name}* — **the actual court, finally named**
**GROUP** 4 of 4 · everybody expected

**The only state that names a specific court.** Everywhere else the card says the category, because the court is assigned and may be reassigned. Fifteen minutes before play it is fixed, and the player needs to know where to walk.

*"Tap Getting in for the code and your card QR."*

---

## GROUP 8 — CANCELLED · four terminal states

*All four are `ended` tone and red. All four are irreversible. All four exist separately because they are four different stories and the player deserves to know which one happened.*

### `cancelledIncomplete` — **Cancelled**
`ended` · `CANCELLED` · *never completed · T−2h*

**GUARD** — `formCancelled` is true

**IN**
- any forming, held or protected state ← **the clock crosses `check`** while `committedAt` is null and the match is not full

**OUT** — none. Terminal.

**COURT** Released back to the club
**GROUP** *n* of 4 — it never filled

**Everybody who paid is refunded in full — nobody was ever committed.** The court went back with two hours for the club to resell it, which is the entire point of the checkpoint.

*"Three matches near you at a similar hour are suggested below."*

---

### `cancelledCheckpoint` — **Cancelled**
`ended` · `CANCELLED` · *certainty checkpoint · rebooking club*

**GUARD** — `checkpointCancelled` is true

**IN**
- `rescue` ← **the clock crosses `check`** with the match committed, short, and the club offering protected rebooking

**OUT** — none. Terminal.

**COURT** Released back to the club
**GROUP** 3 of 4 — the seat was never refilled

**The three who stayed get club credit, already in their account.** The leaver forfeits their share — *"that is what pays the club for releasing the hour."*

**This is the only outcome in the model where a player loses money**, and it is the reason the leaver was shown all four possible refund outcomes before they left rather than one number.

*"Two hours of notice, which is the point of the checkpoint."*

---

### `cancelledClub` — **Cancelled**
`ended` · `CANCELLED` · *club, court or weather*

**GUARD** — `clubCancelled` is true and `inventoryLost` is false

**IN**
- **any non-terminal state** ← the club cancels, at any time, for any reason

**OUT** — none. Terminal.

**COURT** Cancelled by *club*
**GROUP** everybody refunded

**Everybody is refunded in full, including anybody who had already left. A Rescue payment, if one had been made, is refunded too.** Nobody's reliability is touched.

**This state can be entered from every other state**, including `ready` and including a match already in play. That is why it sits above `played` in the resolution ladder.

---

### `inventoryLost` — **Cancelled**
`ended` · `CANCELLED` · *no court left to play on*

**GUARD** — `inventoryLost` is true — **tested before `clubCancelled`**

**IN**
- any unsecured, uncommitted state ← **the category sells out before the checkpoint**

**OUT** — none. Terminal.

**COURT** Gone — the last *category* court was sold
**GROUP** *n* of 4 seats paid

**Everybody is refunded in full, including anybody who had already left.**

*"The match was still short, so it had no court held when the club sold the slot. This is the risk the app names from the first screen — a seat is never a court."*

**It sets `clubCancelled` as well**, which is why it must be tested first — otherwise every inventory loss would render as a weather cancellation, and the player would never learn the one risk they were actually carrying.

---

## GROUP 9 — AFTER THE MATCH · 24 hours, then history

### `needsResult` — **Needs result**
`watch` · `COMPLETED` · *thirty minutes, any of the four*

**GUARD** — `now ≥ matchEnd` · no score · `now < resultWindow` · played complete · no no-show

**OUT**
- somebody enters a score → **`confirmResult`** *(for the other side)*
- `now ≥ resultWindow` → **`playedNoScore`** *(Driver 1)*

*"Any of the four can enter it — not the creator, not a nominated scorer. 30 minutes from the last point, or it counts for nobody."*

---

### `confirmResult` — **Confirm the result**
`watch` · `COMPLETED` · *one tap from the other side*

**GUARD** — a score exists, not yet confirmed, and **you are on the opposing side**

**OUT**
- you confirm → **`completed`**
- `now ≥ resultWindow` → **`playedNoScore`**

*"A teammate agreeing with a teammate proves nothing."* Confirmation must come from the other side — which is why this state is player-relative in a way no other state is.

---

### `completed` — **Completed**
`good` · `COMPLETED` · *levels already moved*

**GUARD** — `confirmed` is true

**OUT** — `now ≥ keepUntil` → history

Shows the score, the level movement, and the Player Score change: *"+1 · turned up, paid, confirmed."*

---

### `playedShort` — **Played**
`idle` · `COMPLETED` · *played a player short*

**GUARD** — `now ≥ matchEnd` · `filled < n`

**IN**
- `rescueLate` ← the join cutoff passed with the seat unfilled, at a standard club

*"The three of you used the hour — the seat was funded either way."* **Not counted** — a level needs four players to mean anything. The leaver is refunded nothing and their reliability takes the hit.

---

### `playedNoShow` — **Played**
`idle` · `COMPLETED` · *somebody did not turn up*

**GUARD** — `noShow` is true

*"No refund, and no search could run — that is what makes it worse than leaving."* **Not counted.** −18 Player Score, and a second inside 90 days restricts peak hours.

**This is the model's strongest sanction, and the reasoning is in the sentence.** Leaving triggers a search that might save the evening. Not turning up removes even that possibility.

---

### `playedNoScore` — **Played**
`idle` · `COMPLETED` · *nobody entered a score*

**GUARD** — `now ≥ resultWindow` · no score

*"All four lose a point of Player Score — it is a shared job."*

---

## ANTECHAMBER — before enrolment

### `waitlisted` — **On standby**
`idle` · *(no backend state)* · *you are queued, not committed*

**GUARD** — you hold **no seat** and you are on this match's waitlist

**Not an enrolled state.** The match is full and somebody else's; you are queued against a vacancy that has not happened.

**OUT** — a seat frees and you accept and pay → **enrolment**, at whichever state the match is then in

*"You joined the standby list · 0,00 zł."* A waitlist entry never charges anything and never commits to anything. **Order is recomputed against the vacancy that actually occurs**, not fixed when you joined — which is why the card says *"2nd"* rather than *"your place in the queue."*

## ADJACENT — private courts

Four states outside the enrolled-match lifecycle, listed for completeness: `privateReserved`, `privatePartial`, `privateFull`, `privateOpen`. A private court is **bought, not earned** — Rule 1 holds it permanently, and commitment runs purely on the clock because there is no group to complete.

**`privateOpen` is the bridge.** An owner who opens a seat to the marketplace creates something another player can enrol in — and that player's enrolled match is the private court, not an open match. Every public share that is paid reduces the owner's guarantee, złoty for złoty.

# PART 9 — INVARIANTS AND EDGE CASES

## 9.1 Invariants — each should be an executable assertion

```
 1  committedAt, once written, is NEVER unwritten
 2  committedNow ⟹ courtHold.kind = 'hard'              (Rule 3)
 3  committed AND no court                              — UNREACHABLE
 4  committed AND soft hold                             — UNREACHABLE
 5  filled counts only seats with BOTH p AND paid
 6  a committed leave never sets seat.paid = false
 7  an uncommitted leave ALWAYS sets seat.paid = false
 8  share is written once at creation and never changes
 9  no state is reachable that is not produced by the §1.4 ladder
10  every terminal state is irreversible
11  a rescue seat never appears in any public listing
12  the join cutoff terminates the cascade regardless of which stage is firing
13  singles (n=2) never reaches heldSoft                (Rule 10)
14  scrubbing the clock forward then back reproduces every state — EXCEPT committedAt
```

**Invariants 3 and 4 are the ones worth testing hardest**, because a bug producing either would be invisible on screen and catastrophic in effect: a committed match whose court quietly went back.

## 9.2 Edge cases the model handles explicitly

| Case | Behaviour |
|---|---|
| **A match created after its own deadline** | `formingLate` with the *"commits as soon as it is complete"* context, then `confirmedOnFill`. Never warns about a deadline the player passed on purpose |
| **A singles match** | `isProtected` and `isFull` coincide. No soft tier, ever |
| **A match that fills then loses a player** | Stays committed via `committedAt`, drops below `isFull`, enters recovery — **never reverts to forming** |
| **An invitation at 21:00 for tomorrow** | Holds to 23:00 → pushed to 08:00 → truncated only if `commit` falls earlier |
| **Clock scrubbed backwards** | Every derived state un-does correctly. `committedAt` does not un-write |
| **Two open matches, same club, category and hour** | Each gets a genuinely different court. `pickCourt` returns the first **available** one |
| **A player leaves at T−20min** | Past `joinCut`. **No cascade stage of any kind can fire** |
| **A club cancels a match in play** | `cancelledClub` — cancellation beats `played` in the ladder |
| **Everybody refunded on inventory loss** | Including anybody who had already left and taken a partial outcome |

## 9.3 Edge cases the model does NOT handle

**Named honestly, because a production build must decide each.**

| Gap | Consequence | Decision needed |
|---|---|---|
| **Two players leave simultaneously** | Not modelled anywhere. A second `vacated` overwrites the first | Append to one recovery process with two vacancies, or reject the second |
| **The stage interval is a timer, not a schedule** | The prototype advances after a fixed offset rather than waiting for a real decline or timeout | Event-driven: accept, decline, or a hard timeout |
| **Rescue priority is displayed, not computed** | The five factors and the score are static in the interface | Compute all five, including the anti-farming negative term |
| **Merge takes the first compatible match** | Not the best of several | Rank candidates |
| **Standby targeting is described, not executed** | The pool's level range is never checked against the seat's target | Execute it |
| **Soft-hold maximum age (Rule 11)** | Specified but not implemented | Implement, and label it as the club's setting rather than a marketplace rule |
| **Club extending a hold (Rule 12)** | Specified but not implemented | Implement as a floor the club may exceed, never undercut |

# PART 10 — IMPLEMENTATION CONTRACT

## 10.1 The server owns the state; the client renders it

**Every string a player reads is computed server-side.** The client does not hold the state table, does not evaluate the ladder, and does not decide a tag.

**Why:** the player app and the club console both consume this lifecycle. Two implementations guarantee they eventually disagree about what one match is doing — and that disagreement is invisible until a player and a manager are on the phone about the same booking.

**The client may derive for display** — a countdown ticking between fetches — but it may never send a conclusion back. Commands carry intent (*join this match*), never conclusions (*this match is committed*).

## 10.2 The payload

```ts
type EnrolledMatchState = {
  key: StateKey;                            // one of the 33
  tag: string;                              // the pill
  tone: 'good'|'watch'|'time'|'ended'|'idle';
  context: string;                          // the line under the tag
  backendState: string;                     // FORMING · COURT_HELD · CONFIRMED · …
  court: string;                            // facet
  group: string;                            // facet
  alert: string | null;                     // replacement and rescue only
  lines: { settled: boolean; text: string }[];
  cta: { label: string; target: string };
  showAccess: boolean;
  nextTransition: { at: Instant; becomes: StateKey } | null;   // for the countdown
}
```

**`nextTransition` is the one field worth adding beyond the prototype.** A client that knows *"at 14:30 this becomes `rescue`"* can render a live countdown and refetch at exactly the right moment, instead of polling.

## 10.3 Recomputation

**On every read.** No cached state, no scheduled job, no state column.

The cost is *"a handful of integer comparisons per match"* — cheaper than the lookup it replaces, and it buys correctness offline, correctness under a scrubbed clock, and the impossibility of a stale row.

## 10.4 The test matrix

| Dimension | Values |
|---|---|
| Club window | 24h · **12h (Atlantic — where `commit` and T−12h coincide)** |
| Join cutoff | 30 min · 20 min |
| Rebooking policy | **true · false** — the checkpoint branches on it |
| Sport | doubles (n=4) · **singles (n=2, no soft tier)** |
| Seats paid | 1 · 2 · 3 · 4 |
| Clock | **every threshold, hit exactly**, plus ±1 min either side |
| Leave timing | before `commit` · after `commit` before `rescue` · after `rescue` · after `check` · after `joinCut` |
| Cascade outcome | full-price · 50% · consent accepted · consent declined · nobody |

**Hit every threshold exactly.** A generator that samples uniformly across the week misses `commit`, T−12h, T−4h, `check` and `joinCut` — which is every branch point in the model.

## 10.5 The acceptance gate

- [ ] All 33 states reachable and rendered from server data alone
- [ ] The §1.4 resolution order is implemented in that order, with a test proving each rung beats the one below
- [ ] All 14 invariants hold, with 3 and 4 asserted as unreachable
- [ ] All 12 hold-ladder rules and all 7 commitment rules pass mechanically
- [ ] A match that fills, commits, loses a player: **stays committed, stays hard-held**, enters recovery
- [ ] Scrub forward through the week and back: every state reproduces, `committedAt` does not un-write
- [ ] The checkpoint produces all **three** outcomes, including *nothing happens* at a standard club
- [ ] `heldSoft` ⇄ `heldReleased` does not oscillate at exactly T−12h or T−4h
- [ ] `inventoryLost` is tested **before** `clubCancelled`
- [ ] Every terminal state is irreversible
- [ ] Singles never reaches `heldSoft`
- [ ] The client contains no copy of the state table
